# 论文展示视频流水线

做法：先定旁白，用旁白里的词驱动画面。画面里没有任何一个写死的秒数，每个动作都挂在"某句话里的某个词说出口的时刻"上。改文案、换配音、重新合成某一章，画面会自动跟上。

```
narration.json ──► tts_edge.py ───► _sec_*.wav ──► assemble_natural.py ──► vo.wav + data/vo.ts
   (文案)          (按章节整段合成)     (每章一条整段录音)   (保留自然停顿，逐词计时)        │
                                                                                    ▼
           verify_voice.py（中型 Whisper 复听）              Remotion 画面：at("b2", "score")
                                                                                    │
music.mp3 ──► mix_all.py（手画包络压低配乐，太短时自动放慢）──► final.wav ───────────────┤
                                                                                    ▼
                  check_anchors.py ──► 静帧 / 样片确认 ──► 1080p 全片 ──► qa_video_audit.py
                                                                                    │
                       export_subs.py（SRT / VTT / 逐词 JSON） ◄──────────────────────┤
                       web_encode.py（压到附件上限内） ──► site/publish_ssh.py（上传并校验）
```

## 1. 文案：`narration.json`

格式见 `template/narration.example.json`。

- 字段：`text` 是字幕和画面上的原文；`say` 只给 TTS 用，写成方便它念的拼法。缩写用连字符逐字母拼（`B-T-W`），容易念错的数字直接拼出来（`sixty-eight point seven five`）。
- 行 id 的首字母就是所属章节（`b1`、`p3`、`r9`）。`sections` 按顺序列出章节，每章带一条导演提示。
- `timeline` 里放时间轴参数：片头纯音乐时长 `lead`、章节间隙 `chapter_gap`、个别句子前额外留给画面的停顿 `extra`。
- 文案定稿前可以用 `tools/fake_timeline.py` 先生成占位时间轴，先排画面，后配音。
- 语言：`"lang": "en"`（默认）或 `"zh"`。中文按字切分计时，标点并到前一个字上，英文术语和数字整体保留，所以 `at("r1", "48.2")`、`at("m1", "XYZ")` 在中文旁白里一样能用。中文示例见 `template/narration.zh.example.json`。

## 2. 配音：`tools/tts_edge.py`（默认）或 `tools/tts_gemini.py`

- 每个章节一次请求、整段合成，所以句与句之间的语气是连贯的。两个引擎都输出 `_sec_<章节>.wav`，后面的步骤完全一样。
- Edge TTS：免费，不用账号和密钥，联网即可。音色和语速写在 `"tts": {"voice": "...", "rate": "+0%"}`，默认英文 `en-US-AndrewNeural`、中文 `zh-CN-YunyangNeural`，全部音色用 `python -m edge_tts --list-voices` 查。它不读导演提示。
- Gemini TTS：能按章节的导演提示调语气，设置写在 `"tts_gemini"`。走 Google Cloud Text-to-Speech，需要自己的 GCP 项目、`gcloud` 登录并开通 Text-to-Speech API。导演提示里要写目标语速（约每分钟 150 词），不写的话同样的文案会长约 7%。
- 只改了某一章，就只重合成那一章：`... out/vo r`。其余章节的录音原样保留。
- 合成完先跑 `tools/verify_voice.py`（语言从 `out/vo/meta.json` 读），用中型 Whisper 复听一遍，检查缩写和数字的读法。小型 Whisper 只负责计时，它常听错，不能拿来判断读音对不对。

## 3. 时间轴：`tools/assemble_natural.py`

- 整段录音直接上时间轴，不切句，也不统一压缩停顿。只把超过 `cap`（0.95 秒）的停顿截短，截短处做 30 毫秒等功率交叉淡化。
- 全程保持 PCM，只在最后编码一次。多次 MP3 转码会让齿音发糊。
- 用 faster-whisper 给出逐词时间，对齐到原文，生成 `src/film/data/vo.ts`。
- `extra` 用来在某句之前多留几秒给画面，比如在结果章某句前留 3 秒放实验回放。

## 4. 混音：`tools/mix_all.py`

- 配乐的压低靠手画的提前量包络：每段人声开始前 0.95 秒就开始压，到第一个词之前完全压下去；章节间隙里再慢慢抬起来。不用侧链压缩，因为压缩器总在第一个音节之后才反应，会听到"一沉"。
- 人声电平定在 −20 dBFS，最后统一留 1 dB 余量。成片约 −19 LUFS，真峰值约 −2 dBFS。
- 配乐比旁白短时，自动用 atempo 放慢，最多放慢到 0.90 倍；再短就直接报错。

## 5. 画面：Remotion（`template/`）

- 设计画布是 1280×720、30fps，交付时用 `--scale=1.5` 出 1080p。
- 每个场景用 `at(id, phrase)` 自己决定什么时候出现、什么时候退场：
  ```ts
  const o = fade(t, at("b3") - 0.1, at("b3") + 0.45, at("b4") - 0.5, at("b4") - 0.1);
  const k = EASE.out(clamp01((t - at("b2", "score") + 0.1) / 0.5));
  ```
  `at()` 找不到对应的词会直接抛错，不会悄悄退回某个默认时间。
- 卡片上已经逐字写出旁白的句子，要加进 `CFG.silentLines`，避免同屏出现两遍同样的话。
- 字幕、章节标记、动效原语（`RevealText`、`RevealNumber`、`Sweep`、`FilmTexture`）放在 `Shell.tsx` 和 `motion.tsx`。项目特有的设置都集中在 `config.ts`。
- 字体、配色、动效规范见 `02-字体与动效规范.md`。

## 6. 检查与渲染

1. `python -X utf8 tools/check_anchors.py src/film src/film/data/vo.ts`：文案改动后必须跑。BAD 指 id 或词已经不在旁白里；WARN 指出现了写死的秒数。
2. 迭代时只出静帧：先 `npx remotion bundle --out-dir=out/bundle` 打包一次，之后 `npx remotion still out/bundle Full out/x.png --frame=N`。跳过打包重复出图会慢很多；类型检查失败时打包不会执行，这时出的是旧画面。
3. 改动大的地方先出 10–40 秒带声样片（`Clip` 组合，`--props='{"from":26}' --frames=0-449`），确认后再渲全片。
4. 全片：`python -X utf8 tools/gpu_lock_render.py --cwd <工程> -- render Full out/full.mp4 --scale=1.5 --concurrency=4 --codec=h264 --crf=16`。渲染锁保证同一时间只有一个渲染任务，5 分钟的片子约 16 分钟。
5. `python -X utf8 tools/qa_video_audit.py --input out/full.mp4 --json qa.json --sheet qa.jpg` 检查分辨率、黑帧、冻结、响度，并出联系表。报"冻结"时先看对应帧：卡片停在画面上等旁白念完属于正常停留。

## 7. 交付与发布

- `tools/export_subs.py` 输出 SRT、VTT，以及给网页播放器用的逐词 JSON。
- `tools/web_encode.py master.mp4 web.mp4 95`：按时长算码率，压到附件上限以内。5:22 的片子约 2.2 Mbps，体积 88.6 MB。
- `site/publish_ssh.py`：用 tar 通过 ssh 上传，再从公网地址拉取校验：页面字节数一致，视频首尾分段请求都返回 206，且总大小一致。
